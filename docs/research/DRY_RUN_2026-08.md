# 首次執行量測 · 2026-08-26

對照規格第 11 節的預估。**預估錯了兩個地方，其中一個是結構性的問題，不只是數字不準。**

量測分成兩種執行：

- **首次執行** — 資料庫是空的，所有東西都是新的。2026-08-26 實際寫檔執行。
- **每週例行執行** — 資料庫已有 25 篇，去重會擋掉大部分。同日乾跑。

---

## 1. 成本：實際比預估低一半以上

| 項目 | 規格預估（路線 B） | 首次執行 | 每週例行 |
|---|---|---|---|
| 進守門模型 | 約 517 篇／週 | 154 篇 | 121 篇 |
| 守門呼叫 | 約 43 次 | **15 次** | **13 次** |
| 摘要呼叫 | 20–40 次 | 25 次 | 7 次 |
| **總呼叫** | **63–83 次** | **40 次** | **20 次** |
| 耗時 | 未預估 | 1,003 秒 | 540 秒 |

**預估高估了約兩倍**，原因見第 2 節。

以 NVIDIA 的 40 RPM 而言，這個量完全不成問題 —— 瓶頸不是速率，是補摘要階段對出版社的禮貌等待（每主機 10 秒）。

**token 數量量不到。** `classifier` 的 `tokensUnreported` 是 15/15 —— `classifyAll`
回傳的 attempt 紀錄沒有帶 `completionTokens` 這個欄位，所以無從加總。這是規格第 11
節承諾的量測項目之一，目前做不到。要補的話是在 `classify-agent.ts` 把 transport
已經拿到的 token 數往上傳。

## 2. ★ arXiv 的 RSS 一次只帶一天，週報漏掉六天

這是這次量測最重要的發現，而且它不是數字誤差，是**結構性的漏稿**。

實測 `rss.arxiv.org/rss/cs.HC`：39 筆項目，**全部是同一天的日期**。

規格第 3.2 節寫「cs.HC 約 60 篇／天 → 約 420 篇／週」，並據此估算成本。
但 feed 本身只保留當天的公告，所以**每週執行一次，只會看到一天**。

| 來源 | 首次執行看到 | 實際一週的量 |
|---|---|---|
| `arxiv-cs-hc` | 38 | 約 270 |
| `arxiv-cs-cy` | 29 | 約 200 |

也就是說，**目前的設定讓 arXiv 這兩個來源只發揮了七分之一**，而它們是整份清單裡量最大的。
成本預估之所以高估兩倍，正是因為它假設了七天份的量。

### 已修正（2026-08-26）

採用選項 1。兩筆來源改用 `export.arxiv.org/api/query`，
`search_query=cat:cs.HC`、`max_results=300`、依 `submittedDate` 遞減排序，
`feedFormat` 與 `dateStrategy` 一併改為 `atom`。實測涵蓋 15（cs.HC）與 21（cs.CY）天，
單次回應 0.7 MB、1.5 秒。

同一週的乾跑，修正前後：

| | 修正前 | 修正後 |
|---|---|---|
| `arxiv-cs-hc` 進窗 | 28 | **95** |
| `arxiv-cs-cy` 進窗 | 25 | **74** |
| 全站進窗 | 151 | **267** |
| 守門呼叫 | 13 | 22 |
| 新增故事 | 7 | **20** |
| 耗時 | 540 秒 | 804 秒 |

**內容量回來約三倍**，成本仍遠低於 40 RPM 的限額。守門呼叫數（22）現在也接近規格
原本的預估（約 43，那是針對資料庫空著的首次執行）。

`tests/unit/guards.test.ts` 加了一條機械性的守則：**任何啟用的來源都不得使用
`rss.arxiv.org`。** 那個每日 feed 是最順手的網址，而它造成的漏稿看不見。

### 當初考慮過的三個選項

1. **改用 arXiv 的查詢 API 加日期範圍。** 那個介面支援
   `submittedDate:[YYYYMMDD0000 TO YYYYMMDD2359]`，研究階段已經驗證可用，一次就能
   取回整週。改動範圍：`sources.json` 兩筆的 `feedUrl` 與 `dateStrategy`。
   成本會回到規格原本預估的水準（約 43 次守門呼叫）。
2. **每天抓、每週發。** 規格第 11.2 節已經為小 feed 提過這個做法。改動較大：
   需要一個中介儲存。
3. **接受七分之一的覆蓋。** 不建議 —— 漏掉的六天是看不見的，不會出現在任何拒絕統計裡。

選了 1 —— 三個裡改動最小，而且把問題從根上消除。

### 翻頁警告會抓到這件事，但今天演示不出來

Task 13 的機制正是為這種漏稿設計的：arXiv 的 feed 每天整批換掉，所以兩次相隔一週的
執行之間交集是零，警告會發出。

但目前 `pipeline/state/feed-watermarks.json` **還不存在** —— 唯一一次寫檔的執行發生在
那個機制加入之前，之後的都是乾跑，而乾跑刻意不寫狀態。基準檔會在下一次非乾跑的執行時
建立。機制本身由 18 個測試涵蓋（含 run 層的狀態寫入行為）。

## 3. 資料流：2,631 篇看到，25 篇上線

首次執行的完整漏斗：

| 階段 | 數量 |
|---|---|
| feed 看到 | 2,631 |
| 超出時間窗 | −2,174 |
| 只有年月的日期 | −260 |
| 沒有日期 | −15 |
| 重複 | −2 |
| **進入時間窗** | **182** |
| 拿不到摘要 | −28 |
| **有摘要可以判斷** | **154** |
| 守門判定不相關 | −127 |
| **收錄** | **25** |

**收錄率 16%**（25/154）。

### 補摘要三層的實際命中

| 管道 | 首次執行 | 每週例行 |
|---|---|---|
| feed 自己帶 | 91 | 71 |
| OpenAlex 補 | 44 | 32 |
| 抓文章頁（僅 Nature） | 19 | 18 |
| 拿不到 | 28 | 30 |

**三層都在真實資料上發揮作用。** 只給 52 個字元的 Taylor & Francis 靠 OpenAlex 補起來；
Nature 靠文章頁。

### `imprecise-date` 的 260 筆不是異常

規格第 6.1 節根據 Cell Press 預期「只有年月的很罕見，而且都是版權頁」。
ScienceDirect 不是這樣：它的 feed 混了「線上先行」和「已編入期別」兩種狀態，後者只留月份。
那 260 筆多數是**真的研究論文，但它們的線上先行日期是幾週或幾個月前**，週報會在它們新的
那一週抓到。詳見 `pipeline/src/published-at.ts` 的註解。

## 4. 供應商切換是實績，不是理論

首次執行的守門階段：

```
nvidia  成功 11  失敗 2   ← 兩次 HTTP 503
groq    成功 2   失敗 0   ← 接手並成功
failovers: 2
```

每週例行執行也有兩次切換。**NVIDIA 的 503 是常態不是例外**，規格第 12.3 節的觀察成立。

Groq 免費方案的 429 也出現過一次（首次執行的守門階段）—— 那是速率限制，不是故障。

## 6. 給 Ming 人工複核的部分

Ming 已表示守門判斷這部分自己看。以下是最需要眼睛的地方。

### 可能誤殺（標題貼題但被拒絕）

139 筆拒絕中，有 15 筆標題含主題關鍵字。多數拒得對：

- `SyPS: Measuring Sycophancy Prompt Sensitivity in Large Language Models` — 測模型，不是測人 ✓
- `Gated Activation Steering for Reducing Sycophancy` — 模型工程 ✓
- `Parasocial Engagement With Social Media Influencers and Mental Health` — 擬社會關係沒錯，但對象是真人網紅不是 AI ✓
- `Generative AI in Youth Mental Health Apps: Rapid Review` — 綜述，沒有自己的人體資料 ✓
- `Author Correction: WiseMind…` — 勘誤啟事 ✓

**這三筆值得你看一眼，可能判錯：**

- `Perceiving Stories, Seeing Selves: Older Adults' Cognitive and Emotional…` — 標題就寫著老年人，聽起來有受試者
- `Out and Abo(u)t: A Multi-Method Study on the Cognitive Mechanisms of…` — 「多方法研究」通常代表有真人
- `Receiving Online Support Matters: Disentangling the Effects of Seeking…` — 可能有受試者，但主題是否為 AI 需要確認

### 可能誤收（系統／原型論文）

收錄的 25 篇裡，這兩篇是介面或原型論文。規格允許「有真人使用者評估，且評估的是心理、
認知或社會影響」，需要確認它們是否真的有：

- `TractorBeam: Personalized AI Sensemaking Support via Collaborative Machine Annotation`
- `What Makes an Initial Reaction Ready for Discussion?: Multi-Persona AI Support`
